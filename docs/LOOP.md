# 声迹 LOOP — 自主迭代协议

> 本文档定义"自主迭代开发"的执行循环。任何一轮迭代（无论由用户触发
> "继续迭代"还是定时任务触发）都严格按此协议执行。

## 循环体

```
LOOP（单轮）:
  1. 读上下文
     - ROADMAP.md       → 取最高优先级未完成任务（[ ] 或 [~]）
     - docs/NORTH_STAR.md → 确认该任务服务于哪根支柱，避免做偏离目标的事
  2. 实现
     - 代码一律走 Write/Edit 工具（触发安全扫描）
     - 修改前先读目标文件相关段落，避免盲改
  3. 验收（每任务必有可执行判据，三选一）
     a. 脚本级：verify_*.py 输出 PASS/FAIL + 数字指标
     b. API 级：curl/python 请求断言状态码与字段
     c. 代码级：语法检查 + 逻辑审查（标注"代码级验收"，UI 交互留用户手验）
  4. 记录
     - ROADMAP.md 勾选任务，附：日期、验收数据、踩坑记录
     - 失败重试 ≤ 3 次；仍失败则标记 [!] 阻塞 + 原因，转下一任务
  5. 版本策略（按用户 2026-09-26 指示）
     - 不再反复推 GitHub；仅本轮全部结束时做一次本地 commit（不 push）
     - 用户明确要求推送时才 push
  6. 汇报
     - 每轮结束输出：完成任务+数据、下轮候选、阻塞项
```

## 停止条件
- ROADMAP 待办清空（只剩阻塞项）
- 任务需要用户决策（如：付费 API、产品取舍、UI 审美）
- 需要外部输入（当前唯一：P0 真实手机录音）

## 优先级规则
1. 阻塞核心闭环的（让"上传→明信片"跑不通的）
2. 产品灵魂类（哼唱滑杆、地图差异化）
3. 质量与性能
4. 工程卫生

## 新任务来源
- NORTH_STAR 能力矩阵中 ❌/◐ 的项
- 验证失败暴露的问题
- 用户反馈（记入 ROADMAP 顶部"用户反馈池"）
